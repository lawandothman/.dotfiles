## Git and PRs
- PRs are drafts by default. Write the description with the pr skill.
- Run only the tests related to your change, never the full suite locally.

## Comments
- Only comment the why, never the what, and only when a future reader would misread the intent without it.
- Keep comments short, concise and to the point. If a comment is unnecessary and the reason can be inferred from reading the code don't add the comment.

## Context
- Repos live in ~/Developer/work/<repo>.
- My interactive shell is fish. Any command meant for me to paste must be fish-compatible.
